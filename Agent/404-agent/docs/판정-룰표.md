# STEP 1. 이상 판정·행동 룰표 초안

작성일: 2026-10-16  
버전: draft-v2  
상태: **보유 데이터와 데모 사례를 활용한 개발용 초안**. 현장 안전 기준이나 운영 절차로 승인된 문서가 아니다.

## 범위와 원칙

- 입력은 현재 저장된 데모 사례의 상별 전류(A), 상별 역률, 현재 유효전력(kW), 비교 전력(kW), 측정 시각이다.
- 룰 함수가 이상 유형, 우선순위, 근거, 누락값, 등록된 첫 행동과 보고 안내를 결정한다. AI는 결과를 설명하며 수치·심각도·행동·보고 여부를 새로 만들지 않는다.
- 현재 데모 사례에는 이상 지속 시간과 반복 횟수가 없다. 원시 CSV에는 측정 시각이 있어 지속·반복 특징을 계산할 수 있으나, 사건 구분과 결측 처리 기준은 미확정이다. 연기·발열·냄새 같은 현장 증상과 보고 담당자 연락처는 현재 확인한 입력에 없다. 해당 조건의 충족 여부를 추측하지 않는다.
- 모든 임계치는 현재 코드의 **데모 기준**이며, 안전 기준으로 사용하려면 설비 담당자의 확인이 필요하다.

## 현재 코드에 있는 이상 판정

| 조건 | 이상 유형 | 현재 우선순위 | 판단 근거와 출처 |
| --- | --- | --- | --- |
| R/S/T상 중 측정된 전류 하나라도 **100 A 초과** | 과전류 | 높음 | `404-main/server/src/rules.ts`의 `DEMO_THRESHOLDS.overcurrent`; 데모 기준, 현장 근거 미확인 |
| R/S/T상 중 측정된 역률 하나라도 **0.85 미만** | 역률 저하 | 보통 | `DEMO_THRESHOLDS.low-power-factor`; 데모 기준, 현장 근거 미확인 |
| `(현재 유효전력 - 비교 전력) / 비교 전력 × 100`이 **10% 초과** | 전력 소비 증가 | 보통 | `DEMO_THRESHOLDS.power-consumption-increase`; 데모 기준, 비교 시점·운전 조건 적합성 미확인 |
| 세 상 전류의 `최대 평균 편차 / 평균 전류 × 100`이 **10% 초과** | 상간 전류 불균형 | 높음 | `DEMO_THRESHOLDS.phase-current-imbalance`; 프로젝트 제안식, 공식 표준 아님 |

경계값은 코드의 비교 연산자 그대로 적용한다. 100 A, 10%는 초과가 아니고 역률 0.85는 미만이 아니다. 복합 이상은 확인된 유형을 모두 유지하고, 화면의 대표 우선순위는 가장 높은 우선순위를 사용한다. 이때 다른 유형이나 누락값을 숨기지 않는다.

## 행동·보고 안내: 현재 데모 가이드와 확정 필요 사항

| 이상 유형 | 현재 등록된 첫 행동 요약 | 현재 등록된 보고 안내 | 룰표로 확정하기 전 확인할 점 |
| --- | --- | --- | --- |
| 과전류 | 임의 접근·차단·재가동을 피하고 안전거리와 현장 규정을 확인한다. 전류와 시각을 기록한다. | 발열·연기·타는 냄새, 안전거리 확보 불가, 반복 또는 불안정한 운전 시 보고하도록 안내한다. | 보고 대상·수단, 즉시 보고 여부, 현장 증상 입력 방법 |
| 역률 저하 | 보상 장치·배전 설비를 임의 조작하지 않고 값과 시각을 기록해 전기 담당자에게 전달한다. | 전압 변동·이상 소음·냄새·발열 동반, 반복 측정에서도 저하 지속 시 보고하도록 안내한다. | 실제 전압·반복 측정 데이터 확보 여부, 보고 시점 |
| 전력 소비 증가 | 증가만으로 설비를 정지·설정 변경하지 않고 현재값·비교값·운전 조건을 기록한다. | 생산 조건 변화 없이 증가 반복, 이상 소음·진동·발열 동반 시 보고하도록 안내한다. | 현재 생산량·운전 모드·반복 정보가 시스템 데이터에는 없음 |
| 상간 전류 불균형 | 배선·차단기·단자에 손대지 않고 접근을 제한한다. 상별 값과 시각을 기록한다. | 데모 가이드는 자격 있는 전기 담당자에게 즉시 보고하도록 한다. 차단기 동작·이상음·냄새·발열·연기나 반복 시 보고 조건도 제시한다. | '즉시' 기준 및 담당자·연락 수단을 현장 지침으로 확인 |

위 문구의 출처는 `404-main/server/src/fixtures/demoGuides.ts`이다. 이 파일 자체에 **현장 표준으로 검토된 자료가 아닌 데모용**이라고 명시돼 있다. 따라서 화면에 적용할 실제 행동·보고 정책은 현장 담당자 검토 후 확정한다.

보고 판단은 두 항목으로 나눈다.

1. **현재 확인된 사실에 따른 보고:** 룰 또는 입력 데이터로 충족 여부가 확인된 경우에만 '지금 보고'라고 표시한다.
2. **조건부 보고 안내:** 연기·발열 등 시스템에 없는 정보는 '있다면 즉시 보고'처럼 조건으로 항상 첫 화면에 표시한다. 발생 사실을 추측하지 않는다.

## 누락·예외 처리 원칙

- 측정 가능한 상에서 이상이 확인되면 그 이상은 표시하고, 누락된 다른 판정은 '확인 필요'로 따로 표시한다.
- 어떤 상도 기준을 넘지 않았더라도 필요한 상별 값이 빠져 있으면 전체를 '정상'으로 표시하지 않는다. 기존 `evalOvercurrent`는 분쇄기(1)의 T상 전류가 누락돼도 `within_threshold`를 반환했다. 공통 룰 v2 구현에서 보류 상태로 수정했으며, 화면에서 '측정된 상은 기준 이내, T상은 미확인'으로 구분해야 한다.
- 전력 비교값이 없거나 0이면 증가율을 계산하지 않는다. R/S/T상 중 역률이 모두 없으면 역률 저하를 판정하지 않는다. 세 상 전류 중 하나라도 없으면 불균형을 판정하지 않는다.
- 사례를 찾을 수 없으면 다른 설비 사례로 대체하지 않는다. 누락 시에는 누락 항목과 담당자에게 확인 요청할 내용을 표시한다.

## 구현 전에 결정할 항목

- 각 데모 임계치의 근거와 실제 현장 적용 가능 여부를 누가 검토·승인할지
- 설비별로 같은 기준을 쓸지, 설비 유형·정격별 기준이 필요한지
- '지금 보고'를 판정하는 입력 자료와 담당자·보고 경로
- 연기·발열·반복 같은 현장 정보를 누가 입력할지, 없을 때 어떻게 표시할지
- 대시보드와 에이전트가 사용할 **단일 판정 결과**의 소유 위치와 버전
- 복합 이상에서 첫 행동이 서로 다를 때 어떤 승인된 안전 절차를 우선 표시할지

개발용 데모 구현은 이 초안을 기준으로 진행할 수 있다. 미확정 항목은 확정값처럼 사용하지 않으며, 실제 운영 적용 전 별도 검토한다.

## 개발용 통합 룰표

모든 임계값·우선순위·행동·보고 정책의 확정 상태는 **데모**다. 높음/보통은 개발용 우선순위이며 실제 긴급도 승인을 뜻하지 않는다. 기존 코드의 판정과 아래 제안의 누락·보고 상태를 구분한다.

| 룰 ID | 적용 범위·필요 입력 | 조건·이상 유형 | 데모 심각도/우선순위 | 지금 할 일 | 보고 판정·안내 | 근거 |
| --- | --- | --- | --- | --- | --- | --- |
| `demo-overcurrent-v1` | 상별 전류가 있는 설비; R/S/T 전류(A) | 유효한 상 중 하나라도 >100 A → 과전류 의심 | 높음 | 기존 과전류 가이드의 초기 대응, 값·시각 기록 | 조건 확인 필요: 현장 증상·반복·불안정 운전 여부 미입력 시 즉시 보고를 확정하지 않음 | `rules.ts`의 `DEMO_THRESHOLDS`·`DEMO_PRIORITY`, `demoGuides.ts` |
| `demo-low-power-factor-v1` | 상별 역률이 있는 설비; 0~1로 정규화된 역률 | 유효한 상 중 하나라도 <0.85 → 역률 저하 | 보통 | 임의 조작 없이 표시값 기록, 전기 담당자에게 전달 | 데모 가이드의 초기 대응에는 담당자 보고가 있음. 추가 증상·지속 조건은 별도로 확인 필요 | 같은 코드·가이드; 실제 보고 시점은 미확정 |
| `demo-power-consumption-increase-v1` | 현재·비교 전력이 같은 단위이며 비교값 >0 | `(현재-비교)/비교×100` >10% → 전력 소비 증가 | 보통 | 운전 조건과 현재·비교값 기록, 담당자 공유 | 생산 조건 변화 없는 반복 또는 현장 증상은 현재 입력만으로 확인 불가 | 같은 코드·가이드; 비교 기간·운전 조건 선정 근거 미확정 |
| `demo-phase-current-imbalance-v1` | 유효한 R/S/T 전류 모두 존재, 평균 >0 | `max(abs(상전류-평균))/평균×100` >10% → 상간 전류 불균형 | 높음 | 임의 접촉 없이 기존 가이드의 접근 제한·기록 안내 | 데모 가이드 기준 전기 담당자에게 즉시 보고 안내. 실제 운영 정책은 검토 필요 | 같은 코드·가이드; 불균형 식은 프로젝트 제안식 |

설비별 정격 정보가 없으므로 위 기준을 모든 설비의 실제 위험 기준으로 일반화하지 않는다. 전압 이상, 센서 고정, 식별값 이상 등 모델이 다른 항목을 탐지했을 때는 기존 네 유형으로 강제 변환하지 않는다.

## 입력 정규화와 지속·반복 특징

- 원시 PM-3 CSV 샘플의 역률은 `87.31`처럼 저장되고 데모 입력은 `0.8731` 같은 비율을 사용한다. 원시 역률의 단위·범위를 자료 제공자에게 확인하고, 출처별 단위 계약이 확정된 입력만 변환한다. 값 크기만 보고 임의로 100으로 나누지 않는다.
- 원시 `activePower`의 단위는 확인이 필요하다. 데모의 kW와 직접 섞지 않는다. 전력 증가율도 현재값과 비교값이 같은 단위·비교 가능한 운전 조건일 때만 계산한다.
- 설명서의 원래 관측 주기는 5초다. 실제 CSV 전체의 시간 간격·중복·누락은 아직 분석하지 않았다. 지속 시간은 타임스탬프로 계산하며 단순 행 수×5초로 확정하지 않는다.
- 지속·반복을 계산할 때 설비·항목·룰별로 구분한다. 관측 공백 허용 길이, 정상 복귀 시 사건 종료 조건, 재발을 새 사건으로 세는 기준, 집계 시간 창을 먼저 정한다. 이 값들은 현재 **미확정**이며 시간·횟수에 따른 심각도 상향과 보고 룰은 아직 비활성이다.
- 알림 행 수와 이상 사건 횟수는 다르다. 모델이 지속 이상을 매 관측마다 출력해도 이를 각각 새로운 사건으로 세지 않는다.

## 함수 결과와 AI 설명의 계약 제안

아래는 후속 구현을 위한 계약이며 현재 코드에 모두 구현되었다는 뜻은 아니다.

| 결과 항목 | 의미 |
| --- | --- |
| `ruleId`, `ruleVersion`, `source`, `approvalStatus` | 적용한 룰·버전·근거·데모/검토 중/확정 상태 |
| `equipmentId`, `observedAt`, `dataSource` | 어떤 설비·시각·원시/데모 입력인지 |
| `status` | `matched` / `within_threshold` / `insufficient_data` / `no_applicable_rule` |
| `anomalyType`, `priority`, `evidence`, `missingFields` | 판정 유형·우선순위·계산 근거·누락값 |
| `actions`, `conditionalReportGuidance` | 등록된 행동과 조건부 보고 문구 |
| `reportStatus`, `reportReason` | `required` / `not_required` / `needs_confirmation`; 보고 판단 근거 |

`reportStatus`는 심각도와 별도로 판정한다. 입력 부족·정책 미확정은 `needs_confirmation`이며 `false`나 보고 불필요로 바꾸지 않는다. `required`는 등록된 정책과 충족된 조건이 있을 때만 반환한다. 현재 초안에는 보고 불필요를 확정하는 정책이 없다. 자동 보고 발송은 이 계약의 범위 밖이다.

필요 입력이 모두 유효한 경우에만 해당 룰의 기준 이내를 확정한다. 일부 상에서 이상이 확인되면 `matched`와 누락 정보를 함께 보존한다. 미등록 유형은 `no_applicable_rule`로 반환하고 담당자 확인을 안내한다. 평균 전류가 0 이하이거나 값이 유효하지 않아 식을 적용할 수 없으면 불균형을 정상으로 단정하지 않는다.

대시보드와 에이전트는 동일한 입력·룰 버전으로 공통 함수를 사용한다. 현재 `src/services/alertRules.ts`와 `server/src/rules.ts`에 분리된 로직은 후속 구현에서 통합할 대상이다. AI에는 확정된 결과와 등록된 문구를 전달하며 유형·우선순위·행동·보고 상태를 변경하거나 고장 원인을 만들어내지 못하게 한다.

## 후속 검증과 추가 자료

- 기존 데모 사례, 임계값과 정확히 같은 값, 누락·비정상 숫자·0인 비교값, 복합 이상, 미등록 유형으로 공통 함수를 검증한다. 위 사례 표는 기존 문서의 결과를 유지한 것이며 이번 문서 보완에서 재실행한 결과는 아니다.
- 단위 계약을 확인한 뒤 원시 시계열에서 룰별 초과 정도·지속·반복 분포를 분석한다. 초과 건수만으로 임계값이 타당하거나 실제 고장이라고 결론내리지 않는다.
- 팀원에게 받을 자료: 설비별 정상 범위 분석, 탐지 시각·항목·원시값, 탐지 방법, 오탐 검토 및 기준의 출처.
- 운영 담당자에게 받을 자료: 정격·허용 범위, 고장·정비 이력, 승인된 조치와 보고 대상·시점·수단.
- 자료 수신 시 관련 룰의 적용 범위·임계값·조치·보고 조건·근거·확정 상태를 갱신하고 버전을 올린다. 룰 변경 후 동일 입력에 대한 대시보드와 에이전트의 결과 일치를 확인한다.


## 2026-10-16 공통 룰 v2 구현 반영

- 실행 원본: `404-main/src/shared/rules.ts`, `decision.ts`, `demoGuides.ts`. 서버의 기존 rules·guide 파일은 공통 소스를 다시 내보낸다.
- 목록과 에이전트는 선택한 알림의 같은 측정값·비교값을 사용한다. 과거의 알림→다른 설비 데모 사례 대응표와 기본 사례 대체를 제거했다. 저장된 전체 데모 사례는 caseId로 명시 조회할 때만 사용한다.
- 전력 증가율은 현재·비교값이 있으면 원래 값으로 계산한다. 판정은 반올림 전 수치로 수행하며 목록의 표시용 변화율도 재계산한다.
- 누락된 상을 기준 이내로 확정하지 않으며 역률 단위 오류·비정상 숫자·0인 비교값·미등록 유형을 처리한다.
- AI 호출 전에 판정·조치·보고 조건이 확정된다. AI 설명 실패와 무관하게 화면의 판정 카드를 유지한다. 보고 초안은 같은 결과에서 코드로 만든다.
- 보고 상태는 `required`와 `needs_confirmation`을 사용한다. 데모 가이드의 역률 저하 담당자 전달과 전류 불균형 즉시 보고를 명시적으로 반영했다. 실제 현장 승인 상태는 모든 룰에서 여전히 데모다.
- 지속·반복 정책, 설비별 실제 임계값, 외부 원시 자료의 단위 계약은 계속 미확정이다. 현재 목록에 있는 반복 표시 수는 사건 횟수나 심각도 상향의 근거로 사용하지 않는다.
- 검증 및 실행 방법은 `404-main/server/README.md`를 참고한다.
