# PlantEye 에이전트 요구사항 (B안 최종본)

작성일: 2026-10-14
근거: `1차 멘토링/에이전트 제작 가이드라인.txt`, `step1-design.md` ~ `step5-feedback.md`
스택: React 대시보드(`404-main`) + TypeScript 백엔드 서버. 이 문서는 Spec의 Requirements에 해당한다.
상태: 설계 확정. 아래 API와 도구는 STEP 6에서 구현한다.

## 사용자와 목표

공장 신입·경력 작업자를 모두 주 사용자로 둔다. 두 사용자 모두 선택한 이상 사례의 근거를 확인하고 다음 점검·보고 행동을 결정할 수 있도록 안내한다.
같은 화면에서 공통 요약과 펼칠 수 있는 상세를 제공한다. 사실·우선순위·보고 조건은 동일하게 유지하고, 사용자는 필요한 상세 수준을 선택한다.

핵심 목표는 '선택한 이상 사례에 대한 유형·우선순위·근거·초기 점검·보고 조건 안내' 하나로 제한한다.
요금·탄소 보고서, 범용 챗봇, 설비 자동 제어는 후속 범위로 둔다.

## 대표 요청

1. "선택한 설비의 이상 사례를 확인해서 어떤 이상인지 알려줘."
2. "이 이상을 어느 우선순위로 확인해야 하고, 판단 근거는 뭐야?"
3. "이 상황에서는 무엇부터 점검하고 어떤 조건에서 담당자에게 보고해야 해?"
4. (STEP 5 반영) "한 번에 다 알려줘" — ①②③을 한 답변 요약으로.

현재 선택한 사례 ID(caseId)를 요청 맥락으로 전달한다. 사례가 없고 요청에도 대상이 없으면 대상을 되묻는다.
대화 중 '그 설비'는 앞서 확인한 대상을 뜻한다. 화면 선택이 바뀌면 새 대상을 명시적으로 반영한다.

## 필수 동작

- LLM이 요청에 따라 도구를 스스로 선택하고, 결과를 받아 추가 호출 또는 최종 응답을 결정한다(에이전트성, 가이드라인 셀프체크 1·2·3).
- 유형 분류·수치 계산·우선순위 판단은 도구(함수)가 한다. LLM은 이를 변경하거나 새 수치를 만들지 않는다.
- 누락값은 0으로 대체하지 않는다. 사례 미존재, 측정 누락, 유형 미평가를 각각 구분한다.
- 점검 행동은 조회된 등록 가이드 안에서만 안내한다. 가이드가 없으면 임의 절차를 만들지 않고 담당자 확인을 안내한다.
- 응답은 3줄 요약 후 "확인된 값 / 미확인·보류" 분리 상세로 제공한다.
- 모든 사례는 데모(가상) 데이터이며 demoOnly로 표시한다. 전기요금·탄소 예측 결과로 이상을 추정하지 않는다.
- 기존 React 화면(`/alerts`)에 통합한다. 별도 Streamlit 화면을 만들지 않는다.
- API 키는 서버 환경변수에만 두고 브라우저·GitHub에 노출하지 않는다.

## 완료 기준

- 대표 요청 4개를 실제 도구 호출 기록(toolTrace)과 함께 시연할 수 있다.
- 같은 사례라도 측정 누락, 유형 미평가, 가이드 없음에 따라 결과가 달라진다.
- 화면의 측정값·기준값·우선순위가 도구 결과와 모두 일치한다.
- 첫 화면은 3줄 이내 요약을 제공하고 확인된 값·미확인·점검 순서·보고 조건을 펼쳐볼 수 있다.
- 신입은 30초 안에 다음 확인 행동과 보고 조건을, 경력자는 30초 안에 우선순위·근거·다음 행동을 찾는 것을 목표로 사용자 유형별로 측정한다.
- API 응답 시간은 사용자 이해 시간과 구분해 첫 실행 후 목표를 확정한다.
- API 오류·데이터 부족을 성공 분석처럼 표시하지 않는다.
- API 키가 브라우저 코드·GitHub에 포함되지 않는다.

## 팀과 확정할 항목

- 이상 탐지 담당자 및 전달 파일 형식. 예측 CSV는 이상 탐지 결과를 대신하지 않는다.
- 실제 CSV 설비명과 UI 설비 ID의 대응표(데모는 자체 ID 사용).
- 실제 임계치·단위·우선순위 정책의 근거(현재는 데모 기준).
- 화면 담당자가 받을 샘플 JSON 형식과 최종 API 연결 방법.
- 배포할 서버 환경, 사용할 모델, API 키 설정 주체.

이 항목 확정 전에도 명시적으로 표시한 데모 사례로 도구와 실행 흐름을 개발할 수 있다.
